# 软件开发 Workflow：精简版需求

版本：v2，2026-10-24。范围依据本次确认：保留通用开发能力，工作台只服务于当前任务。

## 目标与流程

用户选定本地目录、输入需求，需求 Agent 整理提案，用户确认后由编码 Agent 实现，再由审查 Agent 实际检查。失败自动修复，最多三轮，之后结束。

支持单页、多页面及带后端数据库的应用。生成项目的技术栈按需求确认，不限定为单页示例；演示采用简单需求。

## 本次任务

- 新建模式使用已经存在的空目录，不清理用户文件；确认前不写入源码。
- 修改模式允许明确选择已有源码目录，保留现有功能并完成新需求。
- 同时只有一个任务。需求确认前可编辑方案和验收项，确认后固定本轮方案。
- 正在执行时可停止，保留当时源码；下一次需求作为新任务重新确认和检查。
- 关闭服务不恢复任务进度。刷新页面可继续查看同一个服务会话。

## 协作与验收

- 三角色通过共享状态交接已确认提案、编码/启动方案、报告和待修复问题。
- 编码必须实际写文件，生成应用启动成功后才进入浏览器审查。
- 审查只读业务源码，通过实际浏览器、HTTP和登记测试获取证据。
- 每项验收标记通过、失败或未执行。缺项、错误证据或未执行项不能满足完成条件。
- 修复不降低确认要求，首次编码不计修复轮。每个已完成的修复/复查计一轮；构建或启动仍失败也计入。
- 下载、模型或环境故障停止当前任务，显示原因；不进入无上限循环。
- 角色结构化结果缺失时，保留对话上下文最多补全两次，共享原有超时。

## 展示与保存

工作台展示需求/方案、协作进度、应用预览和当前报告。源码直接在所选目录查看。最终报告、运行日志和最多三张关键截图写入项目 `.workflow` 目录；再次运行覆盖该目录的结果文件。

取消历史项目列表、持久化任务数据库、跨重启恢复、修复批次/继续下一批、需求修订号和网页源码树。工作流数据库移除不影响生成应用使用数据库。

## 系统验收

| 场景 | 预期 |
| --- | --- |
| 新建选择非空目录 | 拒绝，已有文件保留 |
| 等待确认 | 仅展示方案，不写源码 |
| 编辑并重复确认 | 采用首次有效确认；不会启动两次 |
| 三类简单开发需求 | 实际写源码、启动并逐项检查 |
| 修复失败或启动失败 | 最多三轮后结束，不再分批等待 |
| 停止执行 | 清理受管进程，保留源码和可保存的结果 |
| 原目录继续修改 | 新任务读取原源码，不沿用旧验收结果 |
| 关闭并重开 | 无旧任务进度；源码与报告仍可在目录查看 |
| 作业打包 | 排除依赖、缓存、真实密钥和运行数据，小于200 MB |
